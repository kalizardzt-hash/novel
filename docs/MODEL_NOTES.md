# 本机模型联调记录

记录日期：2026-09-08 至 2026-09-09。结论仅适用于本次本机加载与测试样例。

## 实际模型与资源

- 用户指定目录中的主权重为 `RVN-Q6_K-multilingual.gguf`，约 20.57 GiB。模型标识由 LM Studio 提供，保存在本地配置中，源码不包含用户的权重绝对路径。
- 本机 Apple M5 Pro，48 GiB 统一内存。
- 262,144 上下文、4 路并发的既有加载状态出现 Metal 内存不足和 `Compute error`。保留原始加载记录后，只重载了这一主模型，改为 16,384 上下文、单路推理，恢复成功。
- 模型宣称的最大上下文不是本机可稳定使用的上下文。应用同时检查实际加载长度与应用预算，不自动改载模型或关闭资源保护。
- 主模型短测约 9–10 tokens/s。完整章节还需要规划、上下文预填、审校、证据复核与提取，不能用单次输出速度直接估计整本小说时间。
- 连续评测期间，LM Studio 原生聊天也使用同一模型。一次正文调用的端到端耗时约 448 秒，实际生成约 42 秒，其余包括队列等待等开销。本轮不是独占性能基准；不同客户端的排队不受小说应用的数据库租约控制。

## 模板适配

实际模板预填 `<think>`，并包含较高推理强度指令。直接使用原始聊天结构化请求时，有效 JSON 可能落入推理通道，正文通道为空。

适配器通过 LM Studio 官方 TypeScript SDK 渲染模板，在关闭思考时为本次请求补齐空思考块，然后以 `complete()` 运行。实际计数与生成共用同一模板。结构化模式与正文分片分别处理，原始模型模板、权重和应用全局设置未被改写。

取消测试实际触达推理后端，约 1.5 秒停止；SDK 可以正常返回 `userStopped`，不能只以“抛出异常”判断是否取消成功。

## 观察到的能力与问题

| 观察                                                 | 工程处理                                                   |
| ---------------------------------------------------- | ---------------------------------------------------------- |
| 能写通顺的中文场景，按 schema 返回结构化结果         | 分场景生成，短指令与明确输出契约                           |
| 局部道具归属冲突样例能识别                           | 保留事实、状态、知识持有人与原文引用                       |
| 审校会把合理悬念、图像描述误判为重大逻辑错误         | 引用校验、单独复核审校意见、保留双方判断                   |
| 整章重写可能引入新问题                               | 自动修订使用唯一原文锚点和不重叠替换                       |
| 已观察到把他人秘密写成主角已知，且同模型审校可能漏检 | 作者字段投影、视角知识过滤、显式信息获取要求；仍须人工抽查 |
| 章节实际字数可能低于目标                             | 显示实写字数与目标进度；不能把规划章数当作实际百万字       |

“Heretic / Abliterated / Uncensored”名称不能证明长篇连续性、规划或审校能力，也不能替代实际测试。

## 本地语义检索

使用官方 `Qwen3-Embedding-0.6B-GGUF` 的 Q8_0 文件，1024 维，约 610 MiB。一个中文检索样例中，相关段落相似度约 0.604，不相关段落约 0.162；这只是冒烟测试，尚非全面检索质量基准。

索引身份包含模型路径、查询格式版本和归一化规则。手工覆盖同路径模型文件后应重建索引；当前没有对大型模型权重进行逐次内容哈希。
