# 见山 · 本地小说创作工作台

一个使用 TypeScript、React 和 OpenAI 兼容模型 API 的本地长篇小说创作系统。支持多作品管理、世界观与人物卡、分卷规划、按场景写作、审校、版本与证据记忆、可恢复后台任务。

当前已通过工程、浏览器和百万字合成容量验证。指定本地模型的连续写作仍有知识越界及自动修订漏检记录，尚未达到完整百万字创作的质量验收标准；详见 [验收记录](docs/ACCEPTANCE.md)。

## 启动

环境：Node.js 24、pnpm，以及任意 OpenAI 兼容模型服务（LM Studio、Ollama、vLLM、DeepSeek、OpenAI 等）。默认面向本机服务；首次安装后，日常创作与检索全部在本机运行。

```sh
pnpm install
pnpm build
pnpm start
```

打开 **http://127.0.0.1:4317**。`pnpm dev` 使用开发前端 http://127.0.0.1:5173。

模型通过标准 API 接入（`/v1/chat/completions`、`/v1/embeddings`、`/v1/models`），在网页“模型与设置”里配置 API 地址、API Key 与主模型标识即可切换任意提供商，应用代码不感知具体模型。空标识只在服务上恰好有一个模型时自动选择。

本地 LM Studio 示例（加载模型并启动 OpenAI 兼容服务）：

```sh
lms server start --bind 127.0.0.1 --port 1234
pnpm doctor
```

本次本机联调将指定 RVN Q6_K 模型从出现 Metal OOM 的 262K 配置恢复为 **16K、单路推理**，未修改权重或关闭资源保护。原配置记录在本机数据目录的 `evidence/lms-before-recovery.json`。不要将模型的标称上下文容量当作硬件实测容量。

## 创作流程

1. 创建作品，填写故事种子、题材、篇幅、视角和文风。
2. 手动建立设定卡，或生成并确认全书蓝图，自动建立主要人物和世界规则。
   蓝图和卷纲可在确认前通过表单直接调整。设定字段可以标记仅供作者规划与审校，避免直接注入正文。
3. 生成、阅读并确认当前卷纲。
4. 选择推进章数。Worker 依次规划场景、写作、审校、修订、提取证据记忆，然后收录章节。
5. 在“创作记录”查看结果、上下文、失败原因与检查点；可以暂停、恢复或取消。
6. 修改设定或前文后，受影响章节会标记为待复核。按顺序审校并收录后，继续写作。
7. 在“故事记忆”更新卷级/全书摘要，并运行收束审计，按来源回查待兑现承诺。

人物、世界、地点、势力、物品、规则、关系、事件与伏笔都有可编辑卡片，支持自定义字段。人物关系卡的起点和终点生成关系图。

生成正文保存在任务检查点中；只有通过质量检查后才会成为正式章节。改写与润色先产生建议版本，作者采用后再保存为草稿，原文历史保留。

自然语言入口能识别意图、解析当前章节指代和根据资料回答问题；涉及修改设定的建议需要作者在卡片上核对并保存。显式的操作按钮绕过模型分类。

## 数据、配置与备份

- 默认数据目录：工作区内 `.novel/`。可用 `NOVEL_DATA_DIR` 指定绝对目录。
- 主数据库：`novel.sqlite`，包括正文、历史修订、实体、记忆、任务、事件与上下文记录。
- 设置：`config.json`，网页可编辑；新任务读取新配置。`NOVEL_PORT` 可覆盖网页服务端口。
- 正文字数统计 Unicode 字母及数字（含汉字），排除标点和空白；不把标题计入正文。
- TXT/Markdown 导入保留原文为草稿，支持 UTF-8 与 GB18030；可一键“顺序审校收录”，遇到重大问题停在对应章节。
- TXT/Markdown 导出包含当前所有章节，包括草稿；状态请在工作台核对。
- JSON 导出包含创作资料、正文历史和有效记忆；导入恢复成独立副本，重新建立语义索引。
- “备份所有作品”使用 SQLite 在线一致性备份，包含任务和运行历史，输出到 `backups/`。
- 恢复 SQLite 备份时先停止应用，使用 `pnpm restore -- <备份路径>`；脚本检验完整性，保留旧数据库并原子切换。
- 浏览器暂存未保存正文，按章节和来源版本隔离；长期保存仍以“保存”按钮为准。

本地 Embedding 默认适配 Qwen3-Embedding-0.6B Q8_0（1024 维）。查询指令、归一化与索引身份在适配模块统一管理。模型或索引不可用时，记录降级原因，继续使用实体与中文全文检索。

## 检查与评测

```sh
pnpm check
pnpm test
pnpm build
pnpm test:e2e
pnpm test:scale
pnpm eval:model
pnpm eval:continuity
pnpm eval:longform
```

浏览器测试使用本机 Chrome 和独立 `.novel/e2e` 数据库，不会生成真实小说。模型评测会调用实际模型。长篇评测默认生成十个约 600 字的连续短章，使用独立数据库并保存检查点、正文和报告，不会混入个人作品。

报告存储在 `.novel/evaluations/`。合成百万字测试只证明工程容量、检索和备份；模型短测只证明对应样例；连续短章也不等于完整百万字文学质量验证。验收状态见 [验收记录](docs/ACCEPTANCE.md)。

## 工程结构

- `apps/web`：网页交互与编辑器。
- `apps/server`：本地 HTTP 接口、SSE、文件与配置。
- `apps/worker`：独立持久化任务执行进程。
- `packages/domain`：小说领域类型、输入契约、证据与确定性校验。
- `packages/application`：创作用例、上下文构建、检索融合；仅依赖抽象接口。
- `packages/infrastructure`：SQLite、模型 SDK、配置和运行装配。
- `packages/prompts`：有版本的任务提示词。
- `packages/evaluation`：真实模型、连续写作与容量评测。

设计依据、关键取舍和故障语义见 [架构说明](docs/ARCHITECTURE.md)。
本机上下文选择、模板适配和已观察到的模型局限见 [模型联调记录](docs/MODEL_NOTES.md)。
