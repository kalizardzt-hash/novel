# 需求审视记录

- **日期**: YYYY-MM-DD
- **原始请求**: （用户原话）
- **审视范围**: 功能 / 架构 / 数据 / 性能 / Bug / 产品方向

## 1. 重构真实目标

用户说的是手段，目的是什么？

例：用户说"换 Milvus 向量库"，真实目标可能是"检索更快"。

## 2. 真实规模走查

百万字 / 几百章 / 深夜连续数小时 / 本地单机下，这个改动走一遍会怎样？

## 3. 预演失败

三周后证明这是灾难，复盘报告写什么？失败往往不在功能本身，而在它没有覆盖的边缘。

## 4. 攻击最弱假设

让这个请求成立的前提（通常 2–4 条），哪条最可疑？

## 5. 扫描静默排除项

用户没提的维度：可用性 / 失败恢复 / 认知负荷 / 数据安全 / 迁移 / 极端输入。

哪些约束用户习以为常到不会说出口？

## 6. 二阶效应

这个能力上线后，使什么变成可能 / 必然 / 新问题？

## 7. 取证

在声明"现有实现不存在 / 会失败"之前，先 grep / git log / 写最小复现。

## 8. 结论

- **继续做**（附调整）
- **重定目标**（附新目标）
- **拆解**（附子任务）
- **不做**（附理由）
